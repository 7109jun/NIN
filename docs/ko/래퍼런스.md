# NIN 레퍼런스

NIN Shell 0.1.0(언어 형식 버전 `"1"`)의 전체 레퍼런스입니다. 안내형 입문서는 Learn NIN을, 플러그인 및 패키지 작성 방법은 Module Development Method를 참고하십시오.

목차: 1 문서 · 2 표현식 · 3 명령문 · 4 함수 · 5 객체 모델 · 6 오류 · 7 정적 검사 · 8 워크플로 · 9 프로세스 · 10 내장 기능 · 11 표준 라이브러리 · 12 CLI · 13 구성 · 14 진단 코드

파이프라인: JSON 파서 → 스키마 검증기 → AST → 의미 분석기 → 타입 시스템 → 런타임 → 워크플로 스케줄러 → Windows 백엔드

## 1. 문서 구조

`.nin` 파일은 스크립트 방언을 사용하는 JSON입니다. `//` 및 `/* */` 주석과 마지막 항목 뒤의 쉼표를 허용합니다. 중복 키는 오류입니다. 알 수 없는 키는 "혹시 다음을 의미했습니까?"라는 수정 제안과 함께 오류로 처리됩니다. 파일은 UTF-8이어야 합니다(BOM은 무시됩니다).

| 키                           | 의미                                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `"nin"`                     | 필수. 형식 버전 문자열 `"1"`                                                                                                              |
| `"name"`, `"description"`   | 문자열                                                                                                                              |
| `"imports"`                 | `{"use":"std.fs"}` \| `{"file":"./x.nin"}` \| `{"package":"pkg"}` 형태의 배열. 선택적 `"as"` 별칭을 지정할 수 있음(기본값: 마지막 경로 요소 / 파일명 / 패키지 이름) |
| `"const"`                   | 이름 → 값, 변경할 수 없는 전역 변수                                                                                                           |
| `"vars"`                    | 이름 → 값, 변경할 수 있는 전역 변수                                                                                                           |
| `"enums"`                   | `{"Color":["Red","Green"]}` 또는 `{"Color":{"Red":1,"Green":2}}`                                                                   |
| `"interfaces"`, `"classes"` | §5 참조                                                                                                                            |
| `"functions"`               | 이름 → 함수 객체(§4 참조)                                                                                                                |
| `"main"`                    | 명령문의 배열: 프로그램 본문                                                                                                                 |
| `"workflow"`                | 워크플로 객체(§8 참조)                                                                                                                   |

가져온 `file`/`package` 모듈은 함수, 클래스, 인터페이스, 열거형 및 전역 변수를 별칭의 멤버로 노출합니다(`util.helper()`, `new util.Box<int>(1)`, `util.PI`). 모듈의 `main`은 실행되지 않습니다. `{"use":"plugin:path"}`는 네이티브 플러그인을 불러옵니다(Module Development Method 참조).

`workflow`가 있고 `main`이 없는 스크립트는 `nin run`으로 시작하면 워크플로를 실행합니다.

## 2. 표현식

값 위치(`value`, `print`, `return`, `throw`, `args` 항목, `with`/`env`/`outputs` 값): JSON 리터럴은 리터럴로 처리됩니다. 배열과 객체는 재귀적으로 평가됩니다. 문자열에는 `${expr}`을 포함할 수 있습니다. 문자열 전체가 정확히 하나의 `${expr}`로 구성되어 있으면 해당 표현식의 타입을 유지한 값을 반환하고, 그 외의 문자열은 문자열로 반환합니다. `$${`는 문자 그대로 `${`를 나타냅니다.

표현식 위치(`if`, `while`, `assert`, `match` 대상, `for…in`, `call`, `set` 대상): 문자열은 표현식으로 파싱됩니다(바깥쪽에 `${…}`를 둘러싸는 것도 허용됩니다). JSON 불리언과 숫자는 리터럴입니다.

리터럴: 정수 `1 0xFF 1_000`, 실수, 문자열 `'single'`/`"double"`(이스케이프 `\n \t \\ \' \" \$ \u{…}`), `true false null`, 리스트 `[a, b]`, 맵 `{key: v, "k2": v, [dyn]: v}`.

후위 연산 및 기본 표현식: 이름, `this`, `a.b`, `a?.b`, `a[i]`(음수 인덱스는 끝에서부터 계산), `a[i:j]`, `f(x)`, `obj.m(x)`, `new Type<Args>(x)`, `super.m(x)`, 람다 `fn(a, b) => expr`, `await e`, `e is Type`, `e as Type`, `c ? a : b`.

연산자 우선순위(낮음 → 높음): `?:` · `??` · `|| or` · `&& and` · `== !=` · `< <= > >= in is` · `+ -` · `* / %` · `**`(오른쪽 결합) · 단항 `! not - await` · 후위 연산자.

의미 규칙

- `+`는 문자열과 리스트를 연결합니다. `==`는 리스트/맵/문자열/숫자에 대해 깊은 비교를 수행합니다(`1 == 1.0`도 참). 객체는 해당 클래스가 `equals`를 정의하지 않는 한 동일성(identity)으로 비교됩니다.
- `/`는 두 피연산자가 모두 정수이고 나눗셈이 정확히 나누어떨어지는 경우 정수를 반환합니다(`6/3 == 2`). 그 외에는 실수를 반환합니다(`7/2 == 3.5`). 정수 피연산자와 음수가 아닌 지수를 사용하는 `**`는 정수를 유지합니다(오버플로 발생 시 실수로 전환).\
  `+ - *`의 정수 오버플로와 0으로 나누기 또는 나머지 연산을 수행하면 `ArithmeticError`가 발생합니다.
- 조건식(`if while && || ! ?:`, `assert`)은 `bool` 또는 `null`이어야 합니다(`null` = false). 다른 타입을 사용하면 `TypeError`가 발생합니다.
- 맵 멤버 접근 `m.k`는 키가 없으면 `null`을 반환합니다. 인덱스 접근 `m["k"]`는 `KeyError`를 발생시킵니다. 리스트 인덱스가 범위를 벗어나면 `IndexError`가 발생합니다.
- 리스트, 맵 및 객체는 공유 참조입니다. 문자열과 숫자는 변경할 수 없는 값입니다.

타입: `null bool int float string list map object function class enum task module` 및 오류 클래스. 타입 주석: `int float string bool any void`, `list<T>`, `map<T>`, `T?`(선택적 타입), `A | B`(유니온), 클래스/인터페이스/열거형 이름, 제네릭 매개변수.

## 3. 명령문

각 명령문에는 \*\*하나의 주요 키(head key)\*\*만 존재합니다. 나머지 키는 수정자입니다. 단독 문자열은 명령문이 아닙니다. 블록은 명령문 배열입니다.

| 주요 키                         | 수정자                                                         | 의미                                                                       |
| ---------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| `let` / `const`              | `type`, `value`                                             | 변수 선언                                                                    |
| `set`                        | `value`, `op` (`+ - * / % ** ??`)                           | 값 할당. 대상은 `x`, `a.b`, `xs[0]`, `this.n`                                  |
| `call`                       |                                                             | 부수 효과를 위해 표현식 평가                                                         |
| `print` / `eprint`           | `end` (기본값 `"\n"`)                                          | 표준 출력 / 표준 오류 출력. 배열 값은 공백으로 연결됨                                         |
| `if`                         | `then`, `else`                                              |                                                                          |
| `while`                      | `do`                                                        |                                                                          |
| `for` (`"x"` 또는 `["k","v"]`) | `in`, `do`                                                  | 리스트 항목 / 문자열 문자 / 맵 키 순회. 변수 두 개를 사용하면 리스트에서는 (인덱스, 항목), 맵에서는 (키, 값)을 받음 |
| `match`                      | `cases:[{when, do}]`, `default`                             | `when`은 값 또는 값의 배열. 첫 번째로 일치하는 항목을 실행                                    |
| `break`, `continue`          |                                                             | 반복문 내부에서만 사용 가능                                                          |
| `return`                     |                                                             | 반환                                                                       |
| `throw`                      |                                                             | 모든 값 사용 가능. `new Error(...)` 사용 권장                                       |
| `try`                        | `catch`+`as`+`type`, 또는 `catches:[{type,as,do}]`, `finally` |                                                                          |
| `run`                        | §9 참조                                                       | 외부 프로세스 실행                                                               |
| `parallel`                   | `max`                                                       | 블록 배열을 동시에 실행하고 모두 완료될 때까지 대기                                            |
| `spawn`                      | `as`                                                        | 비동기 작업 생성. 작업 핸들을 지정한 이름에 바인딩                                            |
| `await`                      | `as`                                                        | 작업 또는 작업 목록이 완료될 때까지 대기                                                  |
| `block`                      |                                                             | 새 스코프 생성                                                                 |
| `assert`                     | `message`                                                   | `AssertionError` 발생                                                      |
| `output`                     | `value`                                                     | 워크플로 단계 출력 설정(워크플로 `script` 단계에서만 사용 가능)                                 |
| `super`                      |                                                             | 부모 생성자 호출(생성자 내부에서만 사용 가능)                                               |
| `exit`                       |                                                             | 지정된 코드로 프로세스 종료(기본값 0). 예외 처리로 잡을 수 없음                                   |

스코프는 어휘적(lexical)입니다. 블록 내부의 `let`은 외부 변수를 가립니다(shadowing). 람다는 자신이 정의된 스코프를 캡처합니다. 최상위 함수는 전역 변수만 볼 수 있습니다.

`type`이 지정되지 않은 `catch`는 `CancelledError`를 포함한 모든 오류를 잡습니다.

## 4. 함수

```
"functions": {
  "add": {"params": ["a: int", "b: int = 1", "...rest"], "returns": "int",
          "async": false, "generics": ["T"], "doc": "…", "body": [{"return": "${a + b}"}]}
}
```

매개변수 형식: `"name"`, `"name: Type"`, `"name: Type = default"`, `"...name"`(가변 길이 리스트), 또는 `{name,type,default,variadic}`.

기본값은 함수가 호출되는 시점에 평가되는 표현식입니다.

인자는 위치 기반으로 전달됩니다. 타입 주석은 런타임에 검사되며, 판별할 수 있는 경우 정적으로도 검사됩니다. `async` 함수는 작업을 반환합니다. `await`는 작업의 결과를 반환하거나 오류를 다시 발생시킵니다.

호출 깊이 제한은 1000입니다(`StateError: stack overflow`).

## 5. 객체 모델

```
"interfaces": {"Shape": {"generics": [], "extends": [], "methods": {"area": {"params": [], "returns": "float"}}}},
"classes": {"Circle": {
  "extends": "Base", "implements": ["Shape"], "abstract": false, "final": false, "generics": ["T"],
  "fields": {"r": {"type": "float", "default": 1.0, "access": "private", "readonly": false, "static": false}, "n": "int"},
  "constructors": [{"params": ["r: float"], "body": [{"super": []}, {"set": "this.r", "value": "${r}"}]}],
  "methods": {
    "area": {"returns": "float", "body": [{"return": "this.r * this.r * 3.14159"}]},
    "scale": [{"params": ["k: int"], "body": []}, {"params": ["k: float"], "body": []}]
  }}}
```

- `fields`: 타입 문자열(축약 형식) 또는 객체. `constructors`(배열)뿐 아니라 `constructor`(단일 객체)도 허용됩니다.
- `methods`: 함수 객체 또는 오버로드 배열. 메서드 플래그: `access`(`public|protected|private`), `static`, `abstract`(본문 없음), `override`, `final`, `async`.
- 캡슐화: `private` = 선언한 클래스 내부에서만 접근 가능. `protected` = 하위 클래스에서도 접근 가능. 위반하면 `AccessError`가 발생합니다(판별 가능한 경우 정적 오류로 처리). 필드는 항상 `obj.f` / `this.f` 형식으로 접근합니다.
- 상속: 하나의 `extends`, 여러 개의 `implements`를 지원합니다. 필드 초기화는 생성자 본문보다 먼저 부모 클래스부터 실행됩니다. 생성자가 없는 클래스는 부모의 생성자를 상속합니다.\
  부모 클래스에 인자 없는 생성자가 없다면 파생 클래스 생성자는 반드시 첫 번째로 `{"super":[…]}`를 호출해야 합니다.
- 다형성: 런타임 클래스에 따라 동적 디스패치를 수행합니다. `super.m()`은 부모 메서드를 호출합니다. 동일한 시그니처를 가진 상속된 구체 메서드를 재정의하려면 `override`가 필요합니다.
- 추상 클래스 / 인터페이스: 인스턴스화할 수 없습니다. 구체적인 하위 클래스는 모든 추상 메서드 및 인터페이스 메서드를 구현해야 합니다.
- 오버로딩: 매개변수 개수, 그다음 매개변수 타입 순으로 선택합니다. 정확히 일치하는 타입, 하위 타입, int→float 확장 변환, `any` 순서로 우선순위가 적용됩니다. 호출이 모호하면 `TypeError`가 발생합니다.
- 제네릭: `new Box<int>(1)`은 타입 인자를 기록하며(reified), 필드/매개변수/반환값 검사에 해당 타입을 사용합니다. 타입 인자가 누락되면 생성자 인자에서 추론하며, 추론할 수 없으면 `any`를 사용합니다.
- 열거형: `Color.Red`는 `.name .value .ordinal`을 가집니다. `Color.values()`, `Color.from_name("Red")`, `Color.from_value(1)`을 사용할 수 있습니다. 동일성으로 비교됩니다.
- 정적 멤버: `Class.field`, `Class.method()` 형식으로 접근합니다. 정적 필드는 클래스 정의 시 한 번 초기화됩니다.
- 내장 인스턴스 메서드: `to_string()`(재정의 가능하며 `str()` 및 `${}`에서 사용), `equals(other)`, `hash()`.
- 리플렉션(`reflect`, 전역): `class_of class_name class classes new fields methods get set invoke parent interfaces is_a type_args is_abstract`.\
  `get/set/invoke`는 공개 멤버에만 접근할 수 있습니다.

## 6. 오류

`throw`는 모든 값을 인자로 받습니다. 모든 오류 객체는 `message`, `code`(소문자로 변환된 클래스 이름), `cause`, `stack`을 가집니다. 계층 구조는 다음과 같습니다.

```
Error
├─ TypeError  ValueError  KeyError  IndexError  ArithmeticError  AssertionError
├─ IOError  ProcessError (has .result)  TimeoutError  CancelledError
└─ StateError  AccessError  ImportError  NameError
```

처리되지 않은 오류가 발생하면 `nin run`은 종료 코드 1로 종료됩니다. NIN 호출 스택과 각 프레임의 `file:line:col` 정보가 포함된 진단 메시지가 출력됩니다.

## 7. 정적 검사 (`nin check`, 모든 `nin run` 실행 전에 수행)

점진적 타입 지정(Gradual Typing): 타입 주석이 없는 항목은 `any`입니다.

오류: 알 수 없는 이름/함수/클래스/타입/모듈, 중복 선언, 함수 호출 인자 개수 불일치(오버로드 인식), `const`에 대한 할당, 잘못된 `this`/`super` 사용, 추상 클래스/인터페이스/열거형 인스턴스화, 추상 메서드 미구현, 누락되거나 불필요한 `override`, 상속 순환, `final` 클래스 상속, `final` 메서드 재정의, 재정의 시 접근 범위 축소, 접근 권한 위반, 제네릭 인자 개수 오류, 알려진 타입 간 타입 불일치, 불리언이 아닌 조건식, 잘못된 피연산자 타입, 반복문 외부의 `break/continue`, 워크플로 스크립트 외부의 `output`, 워크플로 그래프 오류(`needs`에 알 수 없는 항목 지정, 순환, 중복 단계 ID, 알 수 없는 `uses` 함수 또는 `with` 키).

경고: 사용되지 않는 변수(`_`로 시작하는 이름은 제외), 도달할 수 없는 코드, 반환값이 누락될 가능성.

오류가 발생하면 종료 코드 3을 반환하고 실행을 중단합니다. 경고는 출력되지만 실행은 계속됩니다.

## 8. 워크플로

```
"workflow": {
  "name": "ci", "max_parallel": 4, "env": {"CI": "1"},
  "inputs": {"profile": {"type": "string", "default": "debug"}, "fast": {"type": "bool", "required": false}},
  "defaults": {"timeout": "10m", "retries": 0},
  "jobs": {"build": {
    "name": "Build ${matrix.target}", "needs": ["lint"], "if": "success()", "env": {}, "workdir": ".",
    "timeout": "5m", "retries": 1, "retry_delay": "2s", "continue_on_error": false,
    "strategy": {"matrix": {"target": ["a","b"], "include": [{"target":"c"}], "exclude": [{"target":"b"}]}, "fail_fast": true, "max_parallel": 2},
    "limits": {"memory": "512MB", "processes": 16, "cpu_time": "2m"},
    "steps": [
      {"id": "cc", "run": "cargo", "args": ["build"], "outputs": {"log": "${stdout}"}, "on_error": [{"print": "failed: ${error.message}"}]},
      {"id": "s2", "script": [{"output": "answer", "value": 42}]},
      {"id": "s3", "uses": "my_function", "with": {"x": 1}}
    ],
    "outputs": {"artifact": "${steps.cc.outputs.log}"},
    "finally": [{"script": [{"print": "cleanup"}]}]
  }}
}
```

- 그래프: 작업은 `needs`를 통해 DAG(방향성 비순환 그래프)를 구성합니다. 모든 의존 작업이 완료된 작업은 자동으로 시작되며, `max_parallel`을 상한으로 병렬 실행됩니다(기본값: CPU 개수).\
  매트릭스 작업은 각 조합마다 하나의 인스턴스로 확장됩니다(데카르트 곱 + `include` − `exclude`). ID는 `build[target=a]` 형식입니다. 매트릭스 작업을 대상으로 하는 `needs`는 모든 인스턴스가 완료될 때까지 기다립니다.
- 결과: `success | failure | skipped | cancelled`. 모든 `needs` 작업이 성공한 경우에만 작업이 실행됩니다. 단, `if`에 다른 조건을 지정한 경우는 예외입니다(`success() failure() always() cancelled()`).\
  `continue_on_error`는 실패가 종속 작업과 워크플로 전체의 실패로 이어지지 않도록 합니다.
- 단계: `run`(§9와 동일한 키), `script`(격리된 스코프에서 명령문 실행. `output`으로 출력 설정), `uses`(함수 호출. `with` 키는 매개변수 이름에 대응) 중 정확히 하나를 사용해야 합니다.\
  `finally` 항목도 단계입니다. 취소 또는 시간 초과 이후에도 항상 실행됩니다.
- 표현식 컨텍스트: `steps.<id>.{result,outputs,code,stdout,stderr}`, `jobs.<id>.{result,outputs}`, `matrix.*`, `inputs.*`, `env.*`, `workflow.*`, `job.*`, `error`(`on_error` 내부).
- 오류 처리: `retries` + `retry_delay`, `timeout`(프로세스 트리 전체 종료), `on_error`, `continue_on_error`, `finally`, fail-fast(실행 중인 작업 취소, 대기 중인 작업 건너뛰기), Ctrl+C를 통한 전체 워크플로 취소.
- 제한: `limits`는 해당 작업의 모든 프로세스에 Windows Job Object를 사용하여 적용됩니다. 제한을 초과하면 명확한 메시지와 함께 단계가 실패합니다.
- 보고서: `{name, outcome, duration_ms, jobs:[{id,result,duration_ms,attempts,outputs,steps:[…]}]}` 형식입니다. `--report FILE`을 사용하면 보고서를 저장합니다. 요약 테이블이 출력됩니다. 결과가 `success`인 경우에만 종료 코드 0을 반환합니다.\
  프로세스 출력은 실시간 스트리밍되지 않으며 각 프로세스가 종료된 후 `[job/step]` 접두사와 함께 표시됩니다.

## 9. 외부 프로세스

Windows API 기반입니다(`CreateProcessW`, 파이프, Job Objects). `run` 수정자는 다음과 같습니다.

| 키                      | 의미                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `run`                  | 프로그램 이름 또는 경로. PATH + PATHEXT 및 스크립트 디렉터리를 통해 검색합니다. `.cmd`/`.bat`는 `cmd.exe /c`를 통해 실행됩니다.                      |
| `args`                 | Windows용으로 인용 처리되는 argv 목록. 절대 다시 분리되지 않습니다.                                                                     |
| `shell`                | `true`이면 전체 명령줄을 `cmd.exe /c`를 통해 실행합니다.                                                                         |
| `cwd`, `env`           | 작업 디렉터리, 추가 환경 변수                                                                                                |
| `stdin` / `stdin_file` | 데이터 문자열 / 파일 경로                                                                                                  |
| `stdout` / `stderr`    | `"inherit"`, `"null"`, `"capture"`, 또는 `{"file": path, "append": bool}`. stderr에는 `"stdout"`(출력 병합)도 지정할 수 있습니다. |
| `into`                 | `{code, ok, stdout, stderr, duration_ms, timed_out, pid}`를 수신할 변수                                                |
| `check`                | `true`이면 종료 코드가 0이 아닐 때 `ProcessError` 발생(`.result` 포함)                                                          |
| `timeout`              | 밀리초 단위 정수 또는 시간 문자열(`500ms 30s 5m 2h 1d 1h30m`)                                                                  |

프로그램을 찾을 수 없으면 코드 `not_found`를 가진 `ProcessError`가 발생합니다. 크기는 `KB MB GB` 문자열로 지정할 수 있습니다.

## 12. CLI

```
nin                              대화형 셸
nin run FILE.nin [ARGS...]       실행 (작업 디렉터리 = 스크립트 폴더; 더블 클릭으로 실행한 경우 키 입력 대기)
nin FILE.nin [ARGS...]           run과 동일
nin check FILE.nin               파싱 + 검증 + 분석
nin build FILE.nin [-o OUT.exe]  독립 실행 파일로 컴파일 (--icon은 허용되지만 아직 구현되지 않음)
nin fmt FILE.nin [--write]       표준 형식의 보기 좋은 JSON 출력 (주석은 제거됨)
nin eval "EXPR"                  표현식 평가
nin workflow run|list|graph FILE.nin [--job ID]... [--input k=v]... [--report out.json] [--dry-run] [--max-parallel N]
nin pkg install|remove|update|search|list|info|pack|publish ...
nin plugin info|call|list ...
nin schedule add|list|remove|enable|disable|run|daemon|register|unregister ...
nin assoc install|uninstall|status
nin version | nin help
```

종료 코드: 0 성공 · 1 런타임/스크립트 실패 · 2 사용법 오류 · 3 검증/의미 분석 오류 · 130 취소됨(Ctrl+C).

`pkg`: `install SPEC`(`name`, `name@version`, 또는 `.nnpkg` 경로) · `remove NAME [--force]` · `update [NAME]` · `search TEXT` · `list` · `info NAME` · `pack SRC_DIR OUT_DIR` · `publish FILE.nnpkg REGISTRY_DIR`.

`plugin`: `info DLL` · `call DLL FUNCTION [JSON_ARRAY]` · `list`(플러그인 폴더의 DLL 목록).

`schedule`: `add NAME TRIGGER SCRIPT.nin [ARGS…]` 또는 `add NAME TRIGGER -- PROGRAM [ARGS…]` · `list` · `remove|enable|disable|run ID` · `daemon` · `register|unregister ID`(Windows 작업 스케줄러 사용. `boot` 트리거는 관리자 권한 셸 필요).

트리거: `every 5m`, `daily 09:30`, `weekly mon,fri 08:00`, `monthly 15 06:00`, `at 2026-12-01 08:00`, `logon`, `boot`.

`build`: 출력 파일은 검증된 프로그램과 모든 가져온 파일을 뒤에 추가한 `nin.exe`의 복사본입니다. 원본 파일 없이 실행할 수 있습니다. `plugin:` 가져오기는 아직 포함할 수 없습니다.

REPL: 표현식(값 출력, `_` = 마지막 결과), JSON 명령문 또는 스크립트 섹션, `!command`, `:help :vars :funcs :classes :load FILE :reset :cd DIR :history :quit`.

괄호가 닫히지 않은 동안에는 입력을 계속 받습니다.

## 13. 구성

`%APPDATA%\nin\config.toml` (`NIN_CONFIG`를 통해 경로 재정의 가능):

```
[shell]
prompt = "nin> "
history_size = 500
color = true

[run]
pause_on_exit = "auto"      # auto = 더블 클릭으로 콘솔을 연 경우에만 대기 | always = 항상 대기 | never = 대기하지 않음

[paths]
packages = "C:\\Users\\me\\.nin\\packages"
plugins  = "C:\\Users\\me\\.nin\\plugins"

[registry]
sources = ["C:\\registry", "http://example.com/nin"]

[workflow]
max_parallel = 8
```

`NO_COLOR`는 색상을 비활성화합니다. 시작 시 VT 시퀀스와 UTF-8 코드 페이지가 활성화됩니다. `NIN_LOG`는 `std.log`의 로그 임계값을 설정합니다.
